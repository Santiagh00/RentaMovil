TAREAS:
-------
- Crear entidades JPA con anotaciones @Entity, @Table, @Id, @GeneratedValue
- Definir relaciones: @ManyToOne entre Reserva->Cliente y Reserva->Vehiculo
- Configurar cascade y fetch strategies apropiados
- Crear interfaces Repository con Spring Data JPA

- Campos obligatorios con @NotNull, @NotBlank
- Validar formato de email, teléfono, placa de vehículo

DESARROLLADOR 2: SEGURIDAD Y AUTENTICACIÓN
================================================================================

Responsabilidad: Implementar sistema de autenticación JWT, configuración de seguridad.

ARCHIVOS ASIGNADOS:
-------------------
src/main/java/com/rentamovil/config/SecurityConfig.java
src/main/java/com/rentamovil/config/RateLimitFilter.java
src/main/java/com/rentamovil/security/JwtService.java
src/main/java/com/rentamovil/security/JwtAuthFilter.java
src/main/java/com/rentamovil/service/UsuarioDetailsServiceImpl.java
src/main/java/com/rentamovil/dto/AuthRequest.java
src/main/java/com/rentamovil/dto/AuthResponse.java
src/main/java/com/rentamovil/dto/RegisterRequest.java

TAREAS:
-------
- Implementar JWT (JSON Web Tokens) para autenticación stateless
- Crear JwtService: generar token, validar token, extraer username
- Crear JwtAuthFilter: interceptor que valida JWT en cada request
- Configurar SecurityConfig:
  * CSRF deshabilitado (JWT no lo necesita)
  * CORS configurado para frontend
  * Rutas públicas vs protegidas
  * Rate limiting básico
- Implementar UserDetailsService para cargar usuarios desde BD
- BCrypt para encriptación de contraseñas (strength 12)
- Manejo de roles: ADMIN, USER
- @PreAuthorize para control de acceso a nivel de método

ENDPOINTS PÚBLICOS:
-------------------
- /api/auth/login
- /api/auth/register
- /api/vehiculos/disponibles (GET)
- /api/clientes (POST) - registro público
- /api/reservas (POST) - desde portal cliente

TAREAS:
-------
CLIENTE SERVICE:
- CRUD completo de clientes
- Validar que no exista cliente con mismo número de documento
- Búsqueda por documento (para autocompletar en rental)

VEHÍCULO SERVICE:
- CRUD completo de vehículos
- Listar vehículos disponibles
- Contar vehículos por estado (rentados, disponibles)
- Validaciones de placa única

RESERVA SERVICE:
- Crear reserva: validar vehículo disponible, fechas válidas
- Calcular total automáticamente (precio_día * días)
- Cambiar estado de vehículo a "rentado" al crear reserva
- Actualizar reserva: al completar/cancelar, liberar vehículo
- Upload de comprobantes de pago (MultipartFile)
- Validación manual de pagos por admin
- Cálculo de ingresos del mes actual

DATA INITIALIZER:
- Cargar datos de ejemplo al iniciar la aplicación
- Usuarios admin por defecto
- Vehículos de muestra

MANEJO DE EXCEPCIONES:
- ResourceNotFoundException: 404 cuando no existe recurso
- BusinessException: 400 para reglas de negocio violadas
- GlobalExceptionHandler: centralizar respuestas de error

- PUT /api/vehiculos/{id} (ADMIN)
- DELETE /api/vehiculos/{id} (ADMIN)

RESERVA CONTROLLER:
- GET /api/reservas (ADMIN)
- GET /api/reservas/{id} (ADMIN)
- POST /api/reservas (público - portal cliente)
- PUT /api/reservas/{id} (ADMIN)
- POST /api/reservas/{id}/comprobante (público - subir archivo)
- PUT /api/reservas/{id}/validar-pago (ADMIN)

DASHBOARD CONTROLLER:
- GET /api/dashboard (ADMIN)
- Retorna: reservasActivas, ingresosMes, vehiculosRentados, etc.

WEB CONTROLLER:
- Thymeleaf para servir páginas HTML

WEB CONFIG:
- Configurar ResourceHandler para servir /uploads/** estáticamente

FRONTEND ADMIN:
- Login/logout con JWT guardado en localStorage
- Dashboard con estadísticas
- Tablas de gestión: vehículos, clientes, reservas
- Validación de pagos: aprobar/rechazar reservas
- Dark/light theme

FRONTEND CLIENTE:
- Catálogo de vehículos disponibles
- Filtros por tipo (carro/moto)
- Búsqueda por marca/modelo
- Modal de rental en 3 pasos:
  1. Fechas → calcular precio
  2. Datos cliente → autocompletar si existe
  3. Subir comprobante de pago
- Toast notifications para feedback

RESUMEN DE COLABORACIÓN
================================================================================

DESARROLLADOR 1 (Modelos):
  → Dependencias: nenhuma (modelos base)
  → Depende de: nadie

DESARROLLADOR 2 (Seguridad):
  → Dependencias: model/Usuario, repository/UsuarioRepository
  → Depende de: Desarrollador 1

DESARROLLADOR 3 (Servicios):
  → Dependencias: todos los modelos, repositories, DTOs
  → Depende de: Desarrollador 1, Desarrollador 2 (JwtService)

DESARROLLADOR 4 (API + Frontend):
  → Dependencias: servicios, DTOs, configuración de seguridad
  → Depende de: Desarrollador 2 (SecurityConfig), Desarrollador 3 (Servicios)

FLUJO DE DATOS:
---------------
1. Frontend (client.js) → API REST (ReservaController)
2. Controller → Service (ReservaService)
3. Service → Repository → Entidad JPA (Reserva, Cliente, Vehiculo)
4. JWT filter valida token antes de llegar al controller
